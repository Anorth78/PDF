Troubleshooting Performance at Guest-OS Level (VOS

• Load Average Interpretation 
The example represents a single-core (1 vCPU) system, meaning that 
only 1 process can run at any given time.  The load average numbers 
mean 
• over the last 1 minute, the CPU idles for 15% of the time (utilized 
for 85%)
• over the last 5 minutes, the CPU idled for 18% of the time 
(utilized for 82%)
• over the last 15 minutes, the CPU idled for 23% of the time 
(utilized for 77%)
What if the numbers for a single-core system instead read: load average: 1.25,  0.92,  3.75 
• over the last 1 minute, the CPU was overloaded by 25% on average meaning that 0.25 
processes were waiting for CPU
• over the last 5 minutes, the CPU idled for 8% of time (utilized for 92%)
• over the last 15 minutes, the CPU was overloaded by 275% on average meaning that 2.75 
processes were waiting for CPU

--- PAGE 14 ---
Troubleshooting Performance at Guest-OS Level (VOS 
Platform)
• General interpretations 
• If the averages are 0.0, then your system is idle. 
• If the 1 minute average is higher than the 5 or 15 minute averages, then load is 
increasing. 
• If the 1 minute average is lower than the 5 or 15 minute averages, then load is 
decreasing. 
• If they are higher than your CPU count, then you might have a performance problem 
• REMEMBER: when interpreting load average, the number of vCPU must always be considered

--- PAGE 16 ---
Troubleshooting Performance at Guest-OS Level 
(VOS Platform)
Cpu(s) Statistics Row
This row of data shows the percentage of CPU time spent on various tasks.  
Here is break down of what the percentages mean across various task types, along with troubleshooting tips.
• US (user) - CPU time spent executing user-space processes.  
These are higher-level processes, like your application, or the database server running on your machine. 
• SY (system) - CPU time spent executing kernel-space processes. 
The kernel is responsible for low-level tasks, like interacting with the hardware, memory allocation, communicating between OS processes, 
• NI (nice) - the priority level a user space process can be tweaked by adjusting its niceness. ID (idle) - The “idle” CPU state shows the CPU time that’s not actively being used.  
• WA (iowait) - “iowait” is a sub category of the “idle” state. 
•It marks time spent waiting for input or output operations, like reading or writing to disk. 
•When the processor waits for a file to be opened, for example, the time spend will be marked as “ iowait”.  
•Elevated CPU time in the “iowait” category can reveal problems outside of the processor. 
•For example, when an in-memory database needs to flush a lot of data to disk, or when memory is swapped to disk.

--- PAGE 41 ---
• ① Cdcc creates MatrixControl and sends
• ConnPartyReq ② ③ ④ Sends MediaConnectRequest
• ⑤ MediaManager creates MediaExchange for each RTP Hop
• (*) One MediaManager is generated per Connection. Request Media Resource from Media 
Resource Manager (MRM) as needed.
• ⑥ ⑦ MediaExchange creates an Interface according to the Device protocol and 
exchanges Media Capability, IP, Port, etc.
•   (*) SIPInterface (SIP Line & Trunk) H245Interface (H323 Device, GW, Trunk), 
AgenaInterface (SCCP Phone, MOH, Conference Bridge), MTP AgenaInterface (MTP), 
MGCPInterface (MGCP GW)

--- PAGE 50 ---
• If you select Best Effort (no MTP inserted):
• When the caller receives SDP information with Initial INVITE, INVITE 
with SDP (Early Offer) is sent to SIP Trunk without MTP.
• If Initial INVITE does not receive SDP information from the caller, 
send INVITE without SDP (Delayed Offer) to SIP Trunk

--- PAGE 51 ---
• Media Termination Point Required checkbox (SIP Trunk setting)
• If checked, MTP will be allocated unconditionally
• When unchecked, whether or not MTP is used is dynamically 
determined based on conditions such as DTMF and Early Offer.

--- PAGE 52 ---

• If both Transcoder and MTP are required (Codec Mismatch and

• Transcoders may be allocated even if MTP is required, depending on 
Media Resource usage.
• If the Transcoder has a higher priority than the MTP in MRGL, the 
Transcoder will be allocated even if only the MTP is needed.
