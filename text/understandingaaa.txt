EAP Methods
Non-Tunneled / Native EAP Tunneled EAP
EAP-MD5 
• Uses a simple MD5 challenge mechanism.
• Doesn’t provide mutual authentication and derive 
encryption keys 
• Used for basic dot1x testing / legacy deployment.
EAP-TLS 
• Uses certificates for authentication between client and 
server. 
• Authentication happens during TLS handshake and no 
inner method. 
• One of the secure methods as it provides mutual 
authentication and generates encryption keys.
EAP-PEAP 
• Establishes a TLS tunnel using server cert before authentication 
• Uses another EAP Type as an inner method authenticating the 
client using EAP outer tunnel
EAP-FAST 
• Like PEAP, Fast also creates a TLS tunnel and sends client 
credentials securely inside it.
• Uses Protected Access credentials (PAC) for faster 
reauthentication, quick roaming and session resumption 
EAP-TTLS 
• Like Fast and PEAP, TTLS also creates a secure tunnel inside 
which the authentication will be performed. 
• Offers simpler setup and session resumption capabilities 
compared to PEAP.

802.1x Change of Authorization
CoA and Flow ? Mechanism to change network authorization dynamically after 
they have already authenticated.
•
  User/device gets connected to the network initially 
•
  ISE Checks identity & posture and decides initial access 
•
  Access granted (maybe limited or full access) 
•
  Later… something changes! (posture update, guest approved, policy change, etc.) 
•
  ISE sends a CoA message to the NAD 
•
  The network device says: “Got it, let me re-evaluate this session!” 
•
  Session is re-authenticated / re-authorized 
•
  User gets new access without unplugging or reconnecting
