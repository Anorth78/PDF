What is LDAP?
Lightweight Directory Access 
Protocol (LDAP) is an open, 
vendor-neutral protocol for 
accessing and maintaining 
distributed directory information 
services.
Organized as a tree, optimized for 
fast read/search performance 
rather than write operations.
LDAP acts as the standardized 
language. 
Systems like Active Directory or 
OpenLDAP provide the database 
implementation.
Data Model:
Entries: Individual objects (users, 
groups).
Attributes: Metadata describing 
the object (cn, msDS-
UserAccountDisabled, 
memberOf).
Distinguished Name (DN): The 
unique, absolute path to any 
specific entry in the directory 
(CN=ise-
bind,CN=Users,CN=TestCisco)

What is LDAP?
ISE Operations:
Bind: Authentication and session 
initiation.
Search/Compare: Retrieving and 
verifying object data.
Connectivity Standards:
LDAP (Port 389): Standard 
connection.
LDAPS (Port 636): Secure, 
encrypted connection from 
initiation.
Example directory
CN=TestCisco
CN=Users CN=Roles
CN=ise-bind CN=testuser1 CN=Administrators
A DN is the entry's name plus every parent up to the 
root.

Why use LDAP in ISE?
Avoid Domain Join 
Complexity
LDAP is a protocol-level 
integration. You do not need 
to "join" the domain. You 
simply provide ISE with the 
credentials to bind to the 
directory. 
Reduces the administrative 
overhead associated with 
domain trusts.
Authentication and 
Authorization
Authentication: 
• ISE verifies the username 
and password by binding 
to the directory with the 
user's DN. 
Authorization: 
• Groups and attributes 
from the directory feed 
policy conditions. 
Centralized Identity 
Management
Changes to account status 
are applied immediately 
across all integrated network 
services. 
ISE takes the credentials and 
attempts to "Bind" to the 
directory using the user's 
identity. If the directory 
server accepts the 
credentials, ISE is notified of 
the success.

Limitations
Authentication Methods: 
➢ No MS-CHAPv2 or CHAP: LDAP cannot 
validate a challenge/response, so PEAP-
MSCHAPv2 does not work
➢ Plain-text methods work: PAP, EAP-
GTC, TTLS with PAP inside
➢ EAP-TLS can use LDAP for attribute and 
group lookups
Design: 
➢ Plain LDAP on 389 sends passwords in 
clear text: if security is a concern, use 
LDAPS (636).
➢ Groups must be stored by full DN (Group 
Name Attribute = dn) to match 
ExternalGroups
➢ AD LDS partition root is a container, so 
no OUs: every DN uses CN=
