Certificate Types
Default certificates are already installed on Expressway no changes are required. (It 
shows a temporary authorityas the CA) and this is what you get when the server is a 
brand-new install.
Self signed certificates, there are usually created within the Expressway using 
OpenSSL. Not supported by TAC, however it works fine in lab environments.
3rd party certificates will include a certificate chain with Root CA and Intermediate 
CA. This is the case for internal CA’s (Like a Windows Server with CS Role) or public 
CA’s (Like GoDaddy, DigiCert, etc.)

Expressway prevents duplicate self-signed 
certificates with the same Common Name
•Expressway previously allowed the upload of 
two self-signed certificates with identical 
Common Names (CN) to its trusted CA store, 
despite the underlying restriction preventing the 
use of two self-signed certificates with the 
same CN. This behavior could potentially lead to 
confusion or misconfiguration.
•However, this limitation has been addressed in 
subsequent versions, including x14.2 and 
x14.0.7 and upwards. Expressway now 
prevents the upload of a second self-signed 
certificate if a certificate with a matching CN 
already exists in the trusted CA store. This 
enhancement aims to ensure more consistent 
and secure certificate management practices.

Expressway C Certificate Validation Change
Expressway C:
CA Certificates
(root and all intermediates)
Call Manager Trust Stores:
CallManager-trust
tomcat-trust
Starting with version x14.2, Expressway now prioritizes cipher lists 
differently. This change may lead to unexpected TLS connections following 
a software upgrade. Prior to the upgrade, it may have been configured to 
request the Cisco Tomcat or Cisco CallManagerRSA certificate from CUCM 
(or any other product with a separate certificate for the ECDSA algorithm). 
However, post-upgrade, it might prioritize the ECDSA variant, which is 
more secure than RSA.
