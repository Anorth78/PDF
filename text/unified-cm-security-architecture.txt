Server Certificate Count Reduction
BRKCOL-2226
• No need to manage a certificate at every node
The multi-server (SAN) option for self-signed 
certificates means no CA-signed certificate required 
to take advantage of the reduced overhead of 
managing a single service certificate per cluster. This 
includes TVS certificate.
• Fewer service certificates to manage
Reuse the multi-server (SAN) tomcat certificate for 
securing CallManager service connections. In this 
case the tomcat certificate replaces the CallManager 
certificate leaving one less certificate to manage. 
• Remove unnecessary certificates
 Publisher-only CAPF ceritifcate: CAPF certificates 
removed from subscribers.

Long-lived Server Certificates and Upgrades
• While convenient, using certificate with long validity periods is NOT a security best practice. 
Long-lived certificates pose a security risk due to increased exposure time (the longer a 
certificate exists the higher the risk for compromise).
• In cases where the certificate is not public and is not exposed externally, a long lived certificate 
might still be used - for example, the Unified CM ITL Recovey certificate.
• The 20-year ITL Recovery certificate provides a trust anchor for phones across cluster service 
certifcate renewals and system upgrades ensuring that phones maintain trust. 
• The certificate is not exposed beyond the scope of Unified CM and its registered devices nor is 
it freely served on a port call (no answer)

Public CA Certificate Validity Period
WHAT: Reduced Public CA issued/signed certificate lifetime
WHY: To reduce risk of compromised certificates the CA/Browser Forum voted to amend TLS requirements to shorten 
the length of certificate validity. As a result, all Public CAs will begin reducing the maximum certificate lifetime/validity 
length of issued certificates.
WHEN: 
• Beginning March 15, 2026 maximum validity length for an issued certificate will be reduced to 200 days. 
• On March 15, 2027 maximum validity length for issued certificates will be further reduced to 100 days. 
• 2 years later on March 15, 2029 maximum validity length for issued certificates will be reduced to 47 days.
IMPACT: Any public CA signed certificates in a Unified CM deployment must be updated more frequently.
 
** No impact to private CA signed/issued (or self-signed) certificates.**
WHAT CAN YOU DO TO REDUCE IMPACT:
1. Consider using certificates that have longer validity lengths – use private CA signed Unified CM certificates or 
revert to multi-SAN self-signed certificates.
2. If public CA signed certificates are required – leverage server certificate management APIs to help automate 
certificate renewal operations. And use certificate monitoring to enable email notification prior to expiration.

framework that enables secure delegated

• Provides secure, limited access to protected

• No password sharing: Credentials never

limited permissions

expires after set period
• Revocable access: Tokens can be revoked 
without password changes
• Centralized control: Single point for 
access management and auditing
